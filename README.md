# 工作志 Worklog

> 今天到底干了什么？会话记录里有一半，git 里有另一半。这个插件把它们拼起来。

CC GUI 插件。按天读取本机 Claude Code 的会话日志，按工作区分组，再和每个仓库当天的 git 提交、未提交改动对账，先给出一份**零 token** 的事实清单；需要成文时，再让模型把它写成工作日报或个人复盘。

## 它解决什么

写日报时最费劲的不是写，是回想：

- 今天开了几个会话？分别在做哪个项目？
- 哪些事真的做完了，哪些改到一半？
- 报错、返工、放弃的尝试发生在哪里？
- 代码改动和会话里说的对得上吗？

`~/.claude/projects` 里的 JSONL 记录了完整的会话足迹，git 记录了代码侧的结果，但两边都没有一个地方把它们放在一起。工作志做的就是这件事。

## 功能

**事实层（不调用模型）**

- 按日期扫描会话，按**每条消息的时间戳**分天，跨天会话只取当天部分并标记「跨天」
- 过滤工具回包、技能注入、系统提示等非用户输入，只统计真实的用户轮次
- 统计工具调用次数、工具报错、`Edit`/`Write` 改过的文件、执行过的命令
- 按工作区分组，展示每个会话的时间范围、用户要求、最后一条回复
- 与 git 对账：当天提交（hash / 时间 / message）、当前未提交改动

**报告层（按需调用模型）**

- 两种口吻：**工作日报**（今日完成 / 进行中 / 卡点 / 明天接着做）与**个人复盘**（实际做了什么 / 时间花在哪 / 弯路 / 明天怎么改进）
- 明确要求模型区分「已完成」「进行中」「试过但放弃」，并带上来源会话
- 报告可编辑、保存、复制、一键插入输入框
- 默认以只读模式运行，不会改动你的仓库

**入口**

- 中央页签「工作志」
- 侧栏导航入口（带当天会话数 badge）
- 命令面板：`工作志：查看今日工作志`
- 设置区：会话根目录、引擎、模型、工作区、是否做 git 对账、默认口吻

## 使用

1. 打开「工作志」，选日期，点 **扫描当天**。
2. 看来源核对（扫描了多少文件、多少个会话、读取失败几个），再往下看事实。
3. 需要成文时，切到 **日报** 或 **复盘**，点 **生成**。
4. 修改后点 **保存**，或 **插入输入框** 直接接着聊。

首次使用不需要配置：会话根目录留空即使用 `~/.claude/projects`；引擎留空即选择第一个可用引擎。

## 数据与隐私

- 插件**只读**会话文件，从不写入或删除源会话。
- 扫描、事实展示、历史浏览全程不调用模型。
- 只有点「生成」时，事实摘要才会发送给宿主配置的模型；模型可能是云端服务，适用其自身的数据处理规则。
- 报告与扫描结果保存在 CC GUI 的插件数据目录（`plugin-data/worklog/`），不经过插件自建的上传服务。
- 插件声明 `network:none`，没有任何网络请求；需要联网的只有你选择的模型本身。

## 已知限制

- **需要本机能执行 `node` 与 `git`**。扫描器是一个零依赖 Node 脚本，git 对账调用本机 git；宿主只按命令名查找，插件不能传绝对路径。设置页顶部有**环境自检**，会直接显示 `node --version` / `git --version` 的结果；如果显示未找到，先确认已安装并加入系统 PATH，或在设置里补充它们所在的目录（宿主会把这个目录排在搜索顺序最前面）。git 不可用时只影响对账区块，不影响会话扫描。
- **只解析 Claude Code 的 JSONL 格式**。会话里的 `engine` 固定为 `claude`；其它引擎的日志格式不同，未做适配。
- **AI 报告是桌面专享**。用到宿主的 `agent` 能力，Web 版不提供该接口。
- **git 只覆盖仓库里的提交与工作区状态**。终端里执行但未落盘的改动、仓库外的文件操作，不会出现在对账里。
- **按本机本地日期分天**。日期窗口按消息时间戳解释，旅途中切换时区可能把消息归到相邻的一天。
- **事实里有「改动文件」不等于测试通过**。插件只统计工具调用，不判断结果是否被验收。

## 安装

在 CC GUI 侧边栏打开 **插件 → 从本地目录安装**，选中本仓库根目录（有 `manifest.json` 的那一层）即可。

宿主会把整棵目录复制到 `~/.ccgui-next/plugins/worklog/`、写入注册表并**热重载**，不需要重启应用。改完代码再装一次同一目录就会覆盖旧版本。

`scripts/install-local.mjs` 只是给无人值守/CI 场景准备的备用路径；日常安装不需要它。

## 开发

```bash
npm run build     # 把 scripts/scan.mjs 内联进 main.js
npm test          # 扫描器 7 项 + 插件结构 6 项
npm run smoke     # 真实跑通扫描 / git 对账 / 生成 / 保存
npm run validate  # manifest、权限与产物自检
```

源码分两层：

| 路径 | 作用 |
|---|---|
| `src/main.head.js` | 插件主体：UI、调度、存储、agent 调用 |
| `scripts/scan.mjs` | 只读扫描器，零依赖，也可独立命令行运行 |
| `scripts/build.mjs` | 把扫描器以字符串内联进单文件 `main.js` |

扫描器可以单独用：

```bash
node scripts/scan.mjs --root ~/.claude/projects --date 2026-11-19
node scripts/scan.mjs --root auto --date 2026-11-19 --out /tmp/facts.json
```
