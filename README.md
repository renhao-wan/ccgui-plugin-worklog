# 工作志 Worklog

> 今天到底干了什么？会话记录里有一半，git 里有另一半。这个插件把它们拼起来。

CC GUI 插件。按日期范围读取本机 Claude Code 的会话日志，按工作区分组，再和每个仓库同一时间段的 git 提交、未提交改动对账，先给出一份**零 token** 的事实清单；需要成文时，再让模型把它写成工作日报、个人复盘或工作周报。

## 它解决什么

写日报时最费劲的不是写，是回想：

- 今天开了几个会话？分别在做哪个项目？
- 哪些事真的做完了，哪些改到一半？
- 报错、返工、放弃的尝试发生在哪里？
- 代码改动和会话里说的对得上吗？

`~/.claude/projects` 里的 JSONL 记录了完整的会话足迹，git 记录了代码侧的结果，但两边都没有一个地方把它们放在一起。工作志做的就是这件事。

## 功能

**事实层（不调用模型）**

- 按日期范围扫描会话：**单日**、**本周**，或自选起止日期；按**每条消息的时间戳**落到窗口内，跨天会话会标出「跨天」
- 过滤工具回包、技能注入、系统提示等非用户输入，只统计真实的用户轮次；用户粘贴的 HTML/XML/JSX 不会被误当成注入
- 统计工具调用次数、工具报错、`Edit`/`Write` 改过的文件、执行过的命令
- 按工作区分组，展示每个会话的时间范围、用户要求、最后一条回复
- 把「用户要求 → 助手当场的回应」配对，并统计活跃时段、反复编辑的文件、执行过的命令，供报告判断进度与卡点
- 单会话超出上限时保留**最近**的消息、命令与工具报错；跨天会话里前一天的要求会配对到当天第一次回应；用户连续发多条消息时合并成一轮，不会只留最后一条
- 与 git 对账：范围内的提交（hash / 时间 / message）、当前未提交改动
- 交叉对账：把「会话改动过的文件」和「git 里的未提交改动」对起来，列出**会话改过但 git 看不到**（已提交或被还原）与**git 有、这段时间没碰过**的两组文件

**报告层（按需调用模型）**

- 内置三种口吻：**工作日报**（今日完成 / 进行中 / 卡点 / 明天接着做）、**个人复盘**（实际做了什么 / 时间花在哪 / 弯路 / 明天怎么改进）、**工作周报**（本周概览 / 按工作区推进 / 本周产出 / 卡点 / 下周安排）
- 还可以在设置里加**自定义口吻**：填名称和提示词模板，模板里用 `<日期>` 代表当前范围；最多 6 个。每个口吻在设置页默认收起，点开才展开模板编辑区
- 报告面板的口吻行里，**内置三个口吻是固定按钮**，**自定义口吻收在右侧的下拉**里（显示为「自定义口吻」）；当前停在自定义口吻时下拉显示那个口吻并描边标出来。点「日报」「复盘」切走后，下拉**回到未选中状态**（只剩灰色占位文案），口吻行里同时只有一个高亮。口吻再多也不会把按钮挤出可视区
- 选过的口吻会被记住：切到别的页签、插件热重载后再回来，仍然停在刚才那个口吻；设置里的「默认口吻」只在第一次打开、或你改过它之后才生效
- **范围和口吻可以任意组合，但不匹配时会提醒**：三种内置口吻的模板按时间尺度写死（日报有「今日 / 明天」，周报有「本周 / 下周」）。单日范围选周报、或多日范围选日报时，按钮悬停和报告空白区都会说明后果，并建议更合适的口吻；**不会禁用**——你仍然可以坚持自己的选择
- 自定义口吻和内置口吻走**完全同一套**读写逻辑：报告都写进同一个 `reports/` 目录，只是文件名里的口吻不同（见「已知限制」），历史、切换、竞态处理也一致
- 明确要求模型区分「已完成」「进行中」「试过但放弃」，并带上来源会话
- 事实摘要按会话分配长度预算、优先保留最近的消息；工作区多时不会把后面的整段截掉
- 生成结果先只进编辑区，点**保存**才写入文件；日报与复盘各自独立，切换时不会互相覆盖
- 报告可编辑、手动保存、复制全文，可在**原文 / 预览**之间切换查看排版效果（预览支持标题、列表、引用、代码块与表格）
- 生成过程中编辑区会显示模型正在写的字，跟着自动滚到最新一行，末尾有一个闪动光标；首字还没到时是三点依次呼吸加一条扫过的亮带。状态行同时显示已收到的字符数，随时可以点**停止**
- 报告里的**会话短 ID 变成可点击的按钮**，点一下直接跳回那个会话
- **报告历史**按月份分组列出 `reports/` 下已保存的报告（范围 + 口吻）。**月份可以逐个折叠**：默认只展开最近一个月，更早的月份收成一行标题，点一下才展开那一组。**整个历史列表限高滚动**（约 360px），不管展开几个月把页面顶长都有限，攒到几十上百份也不会挤掉下面的内容。报告超过 6 份时列表上方会出现**过滤框**，按日期或口吻名搜（`11-08`、`周报`、`个人复盘` 都行），过滤时月份全部摊开、不用再逐个点。每条都能**删除**（先点一次「删除」变成红色的「确认删除」，再点一次才真删——这是插件里唯一不可撤销的操作）。点一条在**只读浮层**里查看（Esc 或点遮罩关闭），不会碰右侧正在写的报告；想接着改再点浮层里的「在面板中打开」。列目录失败时会直接显示失败原因，不会伪装成「还没有保存过报告」
- **切换范围会读回上次的扫描结果**：每个范围扫完都会把事实快照存进 `runtime/facts-<范围>.json`（保留 30 天）。切回今天、切到本周或重启宿主后，不用再点「扫描」就能看到上次的结果，状态行写明「上次扫描 HH:MM」以区别于刚扫完；git 对账没跟着快照存，会自动补跑一次
- **写到一半的报告不会丢**：未保存的草稿除了留在内存里，还会防抖写进宿主 `storage`（最多 20 份、总计不超过 20 万字符）。插件热重载或重启后重新打开，编辑区里还是那份没保存的内容，状态行照旧标「有未保存的修改」
- **运行引擎时默认按只读模式发起**：插件在 `agent.start` 里把 `readOnly` 设成宿主 `catalog()` 对该引擎报告的 `readOnly` 值，插件自己不会写你的仓库；实际是否只读由宿主与引擎决定

**入口**

- 中央页签「工作志」
- 侧栏导航入口（带当天会话数 badge）
- 命令面板：`工作志：查看今日工作志`
- 设置区：会话根目录、报告保存目录、引擎、模型、引擎运行目录、额外的可执行文件目录（列表）、是否做 git 对账、默认口吻与自定义口吻；改动即自动保存

## 使用

1. 打开「工作志」，选日期范围（单日 / 本周 / 自定义），点 **扫描**。
2. 看来源核对（扫描了多少文件、多少个会话、读取失败几个），再往下看事实。
3. 需要成文时，切到 **日报** / **复盘** / **周报**（或你自定义的口吻），点 **生成**。生成结果只放进编辑区，不会自动落盘。
4. 修改后点 **保存** 才会写入文件；编辑过程中不会自动保存。切到 **预览** 可以查看渲染后的排版（含表格），再切回 **原文** 继续编辑。切换口吻或范围时，未保存的草稿留在内存里，切回来还能接着改；插件重启后也还在。
5. 以前写过的报告在「报告历史」里，按月份分组，默认只展开最近一个月；点月份标题可以展开或收起该月。报告多了可以用列表上方的过滤框按日期或口吻找。点某一条在浮层里只读查看，想看细节不必担心弄丢正在写的内容。要接着改就点浮层里的「在面板中打开」，范围和口吻会一起切过去；不想留着就点该行的「删除」，再点一次「确认删除」。

首次使用不需要配置：会话根目录留空即使用 `~/.claude/projects`；引擎留空即选择第一个可用引擎。所有目录都通过设置页的**选择…**按钮用系统文件夹选择器指定，不接受手动输入。

## 数据与隐私

- 插件**只读**会话文件，从不写入或删除源会话。
- 扫描、事实展示、历史浏览全程不调用模型。
- 只有点「生成」时，事实摘要才会发送给宿主配置的模型；模型可能是云端服务，适用其自身的数据处理规则。
- 报告与扫描结果默认保存在 CC GUI 的插件数据目录（`plugin-data/worklog/`）；可在设置里把报告保存目录改到你选的文件夹（例如同步盘），切换时会把已有的报告与扫描快照搬到新目录（同名文件不覆盖），并清掉宿主留下的 `.bak`。不经过插件自建的上传服务。
- **未保存的报告草稿与扫描快照一样留在本机**：草稿写进宿主 `storage`（最多 20 份、总计不超过 20 万字符，只存你自己写的文本），扫描快照写进插件数据目录的 `runtime/`。两者都不会上传；删除报告、重新保存或把内容改回磁盘版本后，对应的草稿也会清掉。
- **扫描快照里含会话原文片段，不只是统计数字**：`runtime/facts-<范围>.json` 保存了每条用户消息的摘要、助手当场的回应、工具报错文本与执行过的命令（都已按单条长度截断，单会话最多保留最近若干条）。它的作用正是让你不用重扫就能看到上次的结果，但也因此包含了会话内容——把报告目录改到同步盘时，这个文件会跟着一起同步。如果你不希望会话原文离开本机，请保持默认数据目录，或定期清掉 `runtime/` 下的 `facts-*.json`。
- **生成报告时引擎进程默认跑在插件数据目录里**，不是你的项目目录。设置页的「引擎运行目录」在留空时直接显示这个目录的真实路径（形如 `…/.ccgui-next/plugin-data/worklog`，虚框标出「默认」）。引擎每跑一轮都会在 `~/.claude/projects` 留下一条会话记录，`cwd` 就是它运行的位置；放在插件目录下，这条记录归在 `plugin-data/worklog` 名下，不会被下次扫描当成你在某个项目里的工作产出。想让它跑在别处，可以在设置里指定「引擎运行目录」。生成时不会读取该目录下的任何文件。
- 插件声明 `network:none`，没有任何网络请求；需要联网的只有你选择的模型本身。

## 已知限制

- **需要本机能执行 `node` 与 `git`**。扫描器是一个零依赖 Node 脚本，git 对账调用本机 git；宿主只按命令名查找，插件不能传绝对路径。设置页顶部有**环境自检**，会直接显示 `node --version` / `git --version` 的结果；如果显示未找到，先确认已安装并加入系统 PATH，在设置里用**添加目录…**把这些目录逐个加进列表（宿主会把列表里的目录排在搜索顺序最前面，可随时移除）。git 不可用时只影响对账区块，不影响会话扫描。
- **会话日志目前只支持 Claude Code**。扫描器的引擎适配层已经抽出来（`scripts/scan.mjs` 里的 `ADAPTERS`），但只实现了 Claude Code 的 JSONL；Codex、Qoder、Kimi 等其它引擎的日志格式没有真实样本，未做适配。设置页的「数据来源」里也写明了这一点。**这只限制扫描什么日志**——写报告用哪个引擎仍然是设置里单独选的，两者互不影响。
- **显式指定的会话根目录不存在时会直接报错**，而不是显示「今天没有工作」，避免把路径写错误读成空结果。
- **报告按范围与口吻分别存一个文件**：单日 `reports/<日期>-<口吻>.md`，多日 `reports/<起始>_<结束>-<口吻>.md`。**不是每个口吻一个目录**——所有口吻（含自定义）都写进同一个 `reports/`，靠文件名区分；自定义口吻的文件名是 `reports/<范围>-t1.md` 这样。改了范围就拿不到另一份报告，需要重新生成。
- **自定义范围一次最多 92 天**（约一个季度）。再长的窗口接近扫全库，`node` 子进程容易超时；需要更长时间跨度时按季度分几次扫。扫描入口会再校验一次——从历史报告文件名或手改过的快照里带进来的超长范围同样会被拦下。
- **单个会话文件超过 512MB 会被跳过**（原因写进「来源核对」的读取失败数），超过 4000 个 `.jsonl` 时只扫前 4000 个；单行超过 32MB 的也会跳过，避免一条巨型附件行把扫描进程的内存撑爆。
- **AI 报告是桌面专享**。用到宿主的 `agent` 能力，Web 版不提供该接口。
- **git 只覆盖仓库里的提交与工作区状态**。终端里执行但未落盘的改动、仓库外的文件操作，不会出现在对账里。
- **按本机本地日期分天**。日期窗口按消息时间戳解释，旅途中切换时区可能把消息归到相邻的一天。
- **事实里有「改动文件」不等于测试通过**。插件只统计工具调用，不判断结果是否被验收。

## 安装

在 CC GUI 侧边栏打开 **插件 → 从本地目录安装**，选中本仓库根目录（有 `manifest.json` 的那一层）即可。

宿主会把整棵目录复制到 `~/.ccgui-next/plugins/worklog/`、写入注册表并**热重载**，不需要重启应用。改完代码再装一次同一目录就会覆盖旧版本。

`scripts/install-local.mjs` 只是给无人值守/CI 场景准备的备用路径；日常安装不需要它。

## 开发

```bash
npm run build     # 把 scripts/scan.mjs 内联进 main.js
npm test          # 扫描器 20 项 + 插件结构 6 项
npm run smoke     # 真实跑通扫描 / git 对账 / 生成 / 保存 / 多日范围 / 快照读回 / 草稿持久化 / 报告历史搜索与删除 / 自定义口吻
npm run validate  # manifest、权限与产物自检
```

源码分两层：

| 路径 | 作用 |
|---|---|
| `src/main.head.js` | 插件主体：UI、调度、存储、agent 调用 |
| `scripts/scan.mjs` | 只读扫描器，零依赖，也可独立命令行运行 |
| `scripts/build.mjs` | 把扫描器以字符串内联进单文件 `main.js` |

扫描器可以单独用：

```bash
node scripts/scan.mjs --root ~/.claude/projects --date 2026-11-19
node scripts/scan.mjs --root auto --from 2026-11-17 --to 2026-11-19 --out /tmp/facts.json
node scripts/scan.mjs --root auto --date 2026-11-19 --engine claude
```
